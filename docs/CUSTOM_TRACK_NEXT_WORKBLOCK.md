# Next priority — one isolated portable custom course

Baseline: preserve the owner-accepted v0.2.5 native game hash and released
installations. Custom-track implementation takes priority over further stretch
features; continue performance work only against a measured remaining cost.
No supplied source-specific XDELTA becomes universal without its original bytes.
The portable route is authored/exported LEV/VRM, with exact host validation.

## 1. Actual writer/read ownership before shared side effects

Use the existing native file producer -> CtrTrackPrepareFiles/PrepareFileJob ->
owned request -> resident queue/GPU completion and private save namespace. RootReady
now rejects path-only bypass at the consumer. Do not add a second loader/prototype.
Map and integrate before-mutation checks at actual LoadImage/CopyVRAM, ClearImage/
ClearVRAM, MoveImage, RestoreVRAMState, GPU pack/offscreen flush and StoreImage/
readback. A dirty notification AFTER mutation is insufficient. Source readers,
merged dirty rectangles and whole-VRAM restore must participate. Require exact
admission/generation identity; unknown/mixed ownership fails before side effects.
When no custom admission exists, retain the stock path. Failure/timeout retains
leases rather than guessing completion. Prove stock parity and rejected operation
canaries against extracted production functions first; then compile the desktop.

## 2. Single-course publication and teardown

Connect a host-authenticated generated diagnostic LEV/VRM package to one explicit
off-by-default course-host entry. Require rooted verified snapshots, private
records/cards/replay routing, drained incompatible activity and owned resources
before queue publication. Bind level/actor/PVS/cache identity to the same course
generation. Make failure, restart and exit restore stock resources and input/
camera/pause/save ownership. Wait for actual queue/GPU/actor/capture retirement;
never use vblank counts as GPU completion. No live custom-course launch until
this concrete host transaction has tests and a separately staged candidate.

## 3. Physical gate and optimization

First flat drive/collision/checkpoints/lap/restart/exit on the generated course;
then VR90/120 and Photo with OBS/AA. Retain the stock course fallback. Only after
that gate import one owner-supplied compatible authored package. Supplied XDELTA
support remains explicitly source-dependent. Do not overwrite the current disc.

For performance retain the corrected Cortex recording case as demanding reference,
N. Gin/Oxide as additional content cases. Match mode/layout/OBS/AA and compare
race-only windows. Do not claim every course is cheaper than Cortex. Garage,
theatre, multiplayer and flat motion/Photo remain separate subsequent workblocks.
